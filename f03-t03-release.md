# F03-T03 — Создание проверенного неизменяемого релиза

Цель: публиковать валидированный контент и снимок конфигурации в отдельный release ID, не активируя его и не оставляя следов при ошибке.

- [x] Зафиксировать модель создания релиза: входы, источник, пути staging/releases и ограничения конфигурации.
- [x] Добавить хранилище неизменяемого релиза: стабильный ID, конфиг и metadata с безопасными данными об источнике.
- [x] Проверять app type, конфиг, домены сайта и ожидаемые файлы до записи релиза.
- [x] Собрать Markdown в staging-релиз; поддержать config-only release для redirect-приложения.
- [x] Сохранять snapshot и release в SQLite согласованно; не создавать активацию.
- [x] Добавить проверки успешного выпуска, отказа валидации/сборки, неизменяемых файлов и сохранения DB-состояния.
- [x] Обновить roadmap и QA по результатам фактической проверки.

Проверка: `go test ./...`, `go vet ./...`, focused lint без замечаний; full lint фиксирует четыре известных замечания вне текущей задачи.
