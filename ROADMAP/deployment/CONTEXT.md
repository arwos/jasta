# Контекст F03 — Импорт архивов и релизы

## Согласованные решения

- Один архив создаёт один релиз одного сайта; конфигурация редактируется отдельно.
- Поддерживаются ZIP и TAR.GZ; стартовые лимиты 100 МБ на вход и 1 ГБ после распаковки, оба настраиваемые.
- Архив можно загрузить multipart-запросом или скачать с URL. Поддерживаются публичные и приватные registry, HTTP Basic, Bearer и query-подпись.
- Источники разрешены только на внешних HTTPS-хостах. Запрещены loopback/private/reserved IPs; адреса и redirects должны проверяться при фактическом соединении.
- Секреты registry шифруются ключом из отдельного root-owned файла.
- Релизы хранятся без автоматической очистки. Rollback возвращает контент и связанный снимок конфигурации.
- Публикация передаёт web reload-команду; restart web не требуется.

## Хранение и безопасности

- Архивы распаковываются в staging до проверки типа сайта, доменов, front matter и итоговой сборки.
- Запрет path traversal включает абсолютные пути, `..`, escaping symlinks/hardlinks и неоднозначные записи. Проверять лимиты потоком во время распаковки, не по заявленному размеру архива.
- Для URL-fetch повторно разрешать и проверять DNS после redirect; запретить обход через IPv4-mapped IPv6, нестандартные IP-форматы и DNS rebinding. Сохранять исходный URL зашифрованным/редактированным, если он содержит query secret.
- AES-GCM ключ хранить отдельно от SQLite. Разделять права на DB, staging, неизменяемые releases и active snapshot.

## Низкорисковые предположения

- Автоматической очистки нет; ручное удаление можно добавить после отображения использования диска.
- В рамках rollback сайта не меняются глобальные owner, registry credentials и inventory TLS-сертификатов.

## Реализация F03-T01

- Общий пакет `internal/pkg/archive` извлекает ZIP и TAR.GZ в отдельный временный каталог с правами `0700`; при любой ошибке staging удаляется, при успехе каталог принадлежит вызывающему коду.
- Лимиты конфигурируются через `admin.archive`: входной архив — 100 MiB, распакованные файлы и ссылки — 1 GiB, число записей — 100 000. ZIP сначала ограниченно сохраняется в staging и проверяется до разбора центрального каталога; TAR.GZ обрабатывается потоком с проверкой gzip checksum и ограничением распакованного потока.
- Абсолютные, traversal и неоднозначные пути отклоняются. Symlink/hardlink создаются только после обычных файлов; цели ссылок остаются внутри staging, hardlink может ссылаться только на распакованный обычный файл. Специальные типы TAR/ZIP отклоняются, права файлов нормализуются.
- Внутренний API `archive.Extract` готов для вызова deployment-процессом; HTTP upload и интеграция публикации остаются отдельными задачами.

## Реализация F03-T02

- `archive.Fetch` принимает `Source` с URL и Basic/Bearer/query auth; возвращает потоковое тело, совместимое с `archive.Extract`, и ограничивает размер по тем же `admin.archive` лимитам.
- Разрешены только HTTPS URL без userinfo и fragment. Proxy из переменных окружения отключён; транспорт подключается к проверенному IP напрямую, сохраняя исходный hostname для TLS SNI и проверки сертификата.
- DNS проверяется перед запросом, при каждом redirect и повторно непосредственно перед соединением; к сокету передаётся проверенный IP literal. Если в DNS-ответе есть запрещённый адрес, отклоняется весь набор. Redirect разрешён максимум 10 раз; Authorization и Cookie снимаются при смене host/port.
- IPv4/IPv6 policy отклоняет частные, loopback, link-local, shared, multicast, документационные и незарезервированные для глобальной маршрутизации диапазоны, IPv4-mapped private destinations и IPv6 вне глобального `2000::/3`. Для globally reachable NAT64 `64:ff9b::/96` проверяется встроенный IPv4. Список основан на полях IANA `Globally Reachable` в [IPv4 registry](https://www.iana.org/assignments/iana-ipv4-special-registry) и [IPv6 registry](https://www.iana.org/assignments/iana-ipv6-special-registry); явно указанные глобально доступные исключения внутри специальных сетей разрешаются.
- `Source` исключён из JSON/YAML сериализации; ошибки сетевого запроса сохраняют только безопасную категорию и URL без пути/query. Загрузка ограничена таймаутом, response headers — 1 MiB, тело — архивным лимитом.
- Персистентное управление registry credentials и их шифрование остаются на стороне будущих storage/admin команд; `Fetch` получает секреты только в памяти.
