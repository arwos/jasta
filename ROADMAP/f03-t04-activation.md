# F03-T04 — Атомарная активация релиза

## Цель

Активировать один готовый релиз вместе с его config snapshot через существующий reload-сокет, сохранив предыдущую активную пару при ошибке.

## Задачи

- [x] Добавить SQLite-транзакцию выбора site/release/config и построения полного snapshot всех сайтов → unit/integration проверки целостности пары.
- [x] Отправлять candidate snapshot в web до commit БД; при отказе reload откатывать транзакцию → прежняя активация и revision остаются в SQLite.
- [x] Добавить `jasta admin activate` CLI-команду для site ID, release ID, DB и reload socket → help показывает нужные флаги.
- [x] Проверить активацию нескольких сайтов, замену существующей пары и отказ reload → убедиться, что Web получает целиком старый либо целиком новый snapshot.
- [x] Обновить F03 TASK/CONTEXT/QA с фактически выполненными проверками.

## Готово, когда

- [x] Web reload проходит без перезапуска; невалидный candidate или недоступный/отклоняющий reload не меняет активную пару в SQLite.
- [x] Успех обновляет release ID и config snapshot вместе и сохраняет все остальные активные сайты в snapshot.
- [x] `go test ./...`, `go vet ./...` и focused lint проходят; full lint baseline задокументирован.
