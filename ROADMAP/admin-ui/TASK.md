# F06 — React-админка

**Зависимости:** F04-T03, F04-T04, F04-T05; экраны используют F03 и F05.

- [x] F06-T01 — Создать frontend build в `ui/admin/`
  1. Настроить React, TypeScript, Vite, Tailwind CSS с `@tailwindcss/vite`, Oxlint и pnpm.
  2. Добавить воспроизводимый lockfile и команды lint/build; включать build output в `jasta admin` через Go embed.
  3. Раздавать UI и SPA routes только на настроенном admin host; зарезервированные API/WebSocket/upload paths не получают fallback index.
  **Приёмка:** frontend собирается, lint проходит, admin API отдаёт собранное приложение, версии toolchain и runtime requirement задокументированы.

- [x] F06-T02 — Реализовать вход владельца и настройку TOTP
  1. Добавить экран входа владельца по паролю и TOTP, logout и экран подтверждённой сессии. Согласованный enrollment остаётся в `jasta owner-bootstrap`; команда показывает recovery codes ровно один раз, UI не получает их.
  2. Держать access/refresh tokens только в памяти страницы. Обновлять короткий access JWT заранее и повторять защищённый RPC при `unauthorized`; при refresh failure очищать сессию. Reload страницы требует повторного входа.
  **Приёмка:** UI закрывает защищённые разделы до login; пароль/TOTP очищаются после попытки; токены и recovery codes не попадают в DOM, localStorage, sessionStorage или логи; logout отзывает refresh-сессию backend.

- [x] F06-T03 — Управлять сайтами, доменами и конфигурацией
  1. Создавать сайты и показывать список; редактировать конфигурации SPA/MPA/Markdown/Redirect через типовые формы.
  2. Валидировать и сохранять конфигурацию как черновой снимок; новая конфигурация вступает в силу вместе с публикацией, rollback восстанавливает конфиг релиза.
  3. Показывать состояние доменов и сертификатов.
  **Приёмка:** UI отображает серверные ошибки валидации и сохраняет конфиг только после успешного ответа API. Create/update методы проверяют owner session и конфликты доменов; черновик не активируется без релиза.

- [x] F06-T04 — Публиковать архивы и управлять версиями
  1. Добавить multipart-загрузку ZIP/TAR.GZ и публикацию из сохранённого URL-источника; Redirect публикует только config snapshot.
  2. Показывать job progress/reconnect, историю релизов, активную версию и занимаемое место.
  3. Разрешить владельцу отдельно активировать готовый релиз и подтверждать rollback с восстановлением связанного config snapshot.
  **Приёмка:** UI показывает конечный результат/ошибку job; список релизов соответствует backend; новые релизы не активируются автоматически; откат требует явного подтверждения владельца.

- [x] F06-T05 — Управлять registry-секретами и TLS-действиями
  1. Добавить создание/редактирование URL источника и HTTP Basic/Bearer secret.
  2. Добавить действия выпуска/продления сертификатов и состояние выполнения.
  3. Поддержать публичный URL с query-подписью, self-signed для локального домена и Let’s Encrypt для публичного с progress job.
  **Приёмка:** сохранённые секреты не возвращаются UI в открытом виде; ошибки Nginx/ACME показываются без секретных данных; продление не запускается автоматически.

- [~] F06-T06 — Восстанавливать вход владельца после перезагрузки UI
  1. Хранить refresh-токен только в host-only HttpOnly cookie с SameSite=Strict, путём `/jsonrpc`, Secure при HTTPS и сроком действия refresh-сессии; ответы auth не кэшируются и не возвращают refresh-токен в JSON.
  2. Восстанавливать вход при загрузке страницы через `auth.refresh`; access JWT продолжает храниться только в памяти и обновляется ротацией cookie.
  3. При logout отзывать текущую сессию по access JWT и очищать cookie.
  **Приёмка:** после F5 действующая сессия восстанавливается; просроченная или отозванная сессия возвращает экран входа; logout запрещает дальнейший refresh; cookie flags и отсутствие refresh-токена в API-ответе подтверждены проверками.

- [x] F06-T07 — Показывать создание сайта в центральной области
  1. Оставить в боковой колонке список сайтов и кнопку открытия формы.
  2. При создании заменять центральную форму редактирования на форму нового сайта; после успешного создания открывать конфигурацию нового сайта.
  **Приёмка:** длинные поля создания используют центральную ширину; форма не дублируется в списке; отмена возвращает редактор выбранного сайта.
