# F02 — Обслуживание типов сайтов

**Зависимости:** F01-T02, F01-T03.

- [x] F02-T01 — Сопоставлять host с сайтом из активного снимка
  1. Нормализовать host и доменные записи.
  2. Проверять конфликтующие домены и неизвестные host.
  **Приёмка:** каждый домен указывает максимум на один сайт; неизвестный host получает явный ответ ошибки и не попадает на другой сайт.

- [x] F02-T02 — Завершить правила SPA и MPA
  1. Для SPA обслуживать найденные файлы, а для неизвестного пути отдавать корневой `index.html`.
  2. Для MPA directory URL отображать свой `index.html`, отсутствующие файлы возвращать как 404.
  **Приёмка:** тесты покрывают index, вложенные URL, asset-файлы, 404 и попытки выйти за content root.

- [x] F02-T03 — Реализовать RedirectPageApplication
  1. Разрешать домен-источник в правило с целевым доменом и кодом 301/308.
  2. Сохранять path и query запроса.
  **Приёмка:** оба кода работают на каждом правиле, path/query сохранены, редирект не образует цикл при неверной конфигурации. Проверено тестами приложения и snapshot.

- [x] F02-T04 — Собирать MarkdownApplication в HTML
  1. Читать Markdown с YAML front matter и проверять обязательный уникальный `slug`.
  2. Применять общие Go `html/template`, копировать статику и выпускать HTML для URL slug.
  **Приёмка:** `/` задаёт главную страницу; некорректный/повторный slug останавливает сборку; шаблонные данные экранируются, raw HTML Markdown по умолчанию безопасно экранирован. Проверены генерация страниц и выдача статики.
