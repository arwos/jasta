# F04 — Владелец, API и прогресс

**Зависимости:** F01-T02 и F01-T03; операции сайта используют F02/F03/F05.

- [x] F04-T01 — Создавать единственного владельца и TOTP через CLI
  1. Добавлена одноразовая локальная bootstrap-команда с вводом пароля без отображения и обязательным подтверждением TOTP.
  2. Recovery-коды выдаются один раз; в SQLite сохраняются только SHA-256 хэши, использованный код нельзя применить повторно.
  3. Добавлена локальная CLI-команда сброса владельца, recovery-кодов и refresh-сессий.
  **Приёмка:** bootstrap повторно не заменяет владельца; запись создаётся только после валидного кода TOTP и сразу как подтверждённая; в базе нет открытых recovery-кодов.

- [x] F04-T02 — Реализовать JWT-вход и отзыв refresh-сессий
  1. Выдавать EdDSA access JWT на 15 минут; ключ детерминированно выводится из `/etc/jasta/master.key` с отдельным HKDF context.
  2. Проверять пароль и TOTP либо одноразовый recovery code; refresh-токены хранить в SQLite только как хэши, ротировать атомарно с абсолютным сроком до 7 дней.
  3. Реализованы logout и отзыв refresh-сессии по session ID.
  **Приёмка:** подпись проверяется после рестарта с тем же ключом; истёкшие, отозванные, повторно использованные refresh-токены и access JWT с неверной подписью/сроком отклоняются; logout запрещает дальнейшее обновление.

- [x] F04-T03 — Добавить защищённые JSON-RPC команды
  1. Добавлены login/refresh/logout, просмотр владельца, сайтов, конфигов, источников, истории релизов и сертификатов; есть config validate, release activate и rollback.
  2. Добавлен CRUD registry источников; signed query и Basic/Bearer credentials зашифрованы, в API response они не возвращаются.
  3. Bootstrap/reset остаются локальными CLI-командами. Публичны только login/refresh; защищённые методы проверяют JWT и активность session в SQLite.
  4. Контракты request/response/error задокументированы в `CONTEXT.md`; archive upload и сертификатные действия предоставляются F04-T05/F05.
  **Приёмка:** реализованные методы документированы; тесты подтверждают отказ без токена, немедленную блокировку access JWT после logout и конфиденциальность сохранённых registry credentials.
