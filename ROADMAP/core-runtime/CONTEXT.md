# Контекст F01 — Runtime и управляющее хранилище

## Согласованные решения

- Два systemd-процесса: `jasta web` отдаёт контент, `jasta admin` управляет сайтом, деплоем, сертификатами и Nginx.
- SQLite выбрана как база. После уточнения пользователя SQLite доступна только admin; web получает активный снимок сайта и релиза через локальный reload Unix-сокет.
- Переключение версии и конфигурации не перезапускает web.
- Один сайт публикуется из одного архива, конфиг задаётся отдельно и сохраняется в снимке релиза.
- F01-T03 зафиксировал JSON-протокол снимка версии 1: монотонная ревизия и список сайтов с типом и JSON-конфигом. Web подготавливает все приложения и проверяет домены до атомарной замены in-memory маршрутов; ошибочная или устаревшая ревизия отклоняется. Admin CLI отправляет снимок через Unix-сокет и получает подтверждение/ошибку.
- Reload работает только с типами приложений, чья инициализация уже реализована. Markdown и redirect пока остаются заглушками; их паники перехватываются, снимок отклоняется целиком, активное состояние сохраняется.
- F01-T04 добавил `jasta admin import-configs`: импортирует современные SPA/MPA YAML и прежний формат с `single`, `page404`, `assets_folder`. Для старого формата `single: true` преобразуется в SPA, `false` — в MPA; `index.html` задаётся по умолчанию. Конфиги без нужных полей и типы кроме SPA/MPA остаются на месте и выводятся в отчёте.
- Импорт вычисляет стабильный ID из относительного пути YAML, создаёт сайт, домены и начальный снимок конфига в одной транзакции. Повторный запуск распознаёт уже импортированный ID и ничего не перезаписывает; конфликты имени/доменов пропускаются. Относительный `root` нормализуется в абсолютный путь относительно YAML, но исходный YAML и контент не меняются.
- CLI использует Goppy ORM и ту же миграцию схемы; `--database` задаёт файл SQLite (по умолчанию `/var/lib/jasta/admin.sqlite`, можно указать путь из собственного admin config). Миграции запускаются перед импортом. Команду запускать при остановленном admin-сервисе: выбранный SQLite locking mode — `EXCLUSIVE`.

## Состояние репозитория

- Текущая точка входа: `cmd/jasta/main.go`; приложение запускается одним процессом.
- Goppy SQLite connector текущей версии импортирует `mattn/go-sqlite3`; его default config использует `EXCLUSIVE` locking. Пользователь выбрал admin-only DB, чтобы два процесса не делили SQLite-соединения.
- Сейчас сайты читаются из YAML-каталога; production пример устарел. Импорт поддерживаемых старых конфигов должен сообщать о несовместимых файлах, не удаляя их.
- В `go.mod`: Go 1.26.8, Goppy v3.2.3; Goppy предоставляет ORM и миграционные механизмы.

## Источники и ограничения

- [Goppy](https://goppy.osspkg.com/) — официальный обзор плагинов, dependency injection, HTTP server pool и миграций.
- [mattn/go-sqlite3](https://github.com/mattn/go-sqlite3) — CGO-драйвер; требуется `CGO_ENABLED=1` и C toolchain. CGO разрешён владельцем проекта.
- Точный API и конфигурацию сверять с закреплённой в проекте версией Goppy v3.2.3, не с `latest`.

## Проектные инварианты

- SQLite — управляющее хранилище admin; web не зависит от наличия или блокировки БД.
- Web принимает только полностью проверенный снимок. При ошибке reload старая маршрутизация и релиз остаются активными.
- Импорт и будущие миграции не удаляют исходные каталоги конфигов, релизы или контент автоматически.

## F01-T01 — Реализация

- CLI выбирает роль по первому позиционному аргументу `web` или `admin`, затем передаёт оставшиеся флаги Goppy.
- Для `web` регистрируется только `public.Plugin`; для `admin` — только `admin.Plugin`. `grab` остаётся общей CLI-командой. F05-T01 удаляет старую команду `nginx`, которая напрямую перезаписывала глобальный default vhost; конфиг теперь генерируется и применяется через защищённый admin API.
- При отсутствии `--config` web использует `/etc/jasta/config.yaml`, admin — `/etc/jasta/admin.yaml`; production и dev config-файлы разделены. Оба admin-примера слушают `127.0.0.1`.
- Goppy server pool требует tag `main`, поэтому отдельный admin config использует tag `main`, а `admin.tag` указывает на него.
- Runtime smoke подтвердил web 200 и admin 404 на отдельных dev listeners. Первый запуск в sandbox был запрещён политикой bind; повторный запуск с разрешением на localhost прошёл.

## F01-T02 — Реализация

- `internal/storage` подключает Goppy ORM и SQLite migrations только через `api.AdminPlugins`; публичная сборка не включает SQLite plugin.
- Первая встроенная миграция создаёт `settings`, `sites`, `site_domains`, `site_config_snapshots`, `releases`, `site_activations`, `registry_sources`, `owners`, `owner_recovery_codes`, `auth_sessions`, `jobs` и `certificates`, плюс необходимые индексы и ограничения.
- Admin config задаёт `/var/lib/jasta/admin.sqlite`, WAL, exclusive lock и foreign keys; dev config использует отдельную временную базу.
- В проект добавлен точный `github.com/mattn/go-sqlite3` v1.14.47, закреплённый в Goppy v3.2.3. Другие зависимости не обновлялись.
